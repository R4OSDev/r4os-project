# R4OS Project

Oeffentlicher Koordinations-Workspace fuer die eigenstaendigen R4OS-Repositories.
Der produktive Kernel besteht aus Rust und notwendiger x86_64-Assembly;
Apps, Dienste, Libraries, Treiber, Protokolle und der separate Recovery-Kernel
behalten ihre jeweiligen Besitzer und Builds.

    DevKit\        Installierte SDK- und Hostwerkzeuge
    Repositories\  Eigenstaendige R4OS-Quell-Repositories
      Apps\         Anwendungen
      Services\     Dienste
      Diagnostics\  Diagnoseprogramme
      Drivers\      Treiber
      Protocols\    Protokolle
      Subsystems\   Gastlaufzeiten
      Recovery\     Eigenstaendige Reparaturumgebung
    Artifacts\     Lokale Build- und Testergebnisse
    Tools\         Workspace-Setup und GitHub-Verwaltung

Git wird auf beiden Hosts vorausgesetzt. Unter Windows muss PowerShell 7
(`pwsh`) bereits installiert sein. Nach einem frischen Clone unter Windows
`Tools\Setup.bat` oder unter Debian Linux `./Tools/Setup.sh` ausfuehren. Fehlt
`pwsh` unter Debian, richtet der Linux-Starter mit root- oder sudo-Rechten die
offizielle Microsoft-Paketquelle ein und installiert PowerShell vor dem Start
von `Setup.ps1`. Batch und Shell sind ansonsten nur duenne Hoststarter; die
gemeinsame Logik liegt in PowerShell-7-Skripten und bestimmt alle Pfade relativ
zum jeweiligen Skript. Die gemeinsame Datei
`Tools/Credentials/Github.json` wird nur fuer Pushes und
Repository-Verwaltung benoetigt.

GitHub-Zugriffe erfolgen unter Windows ueber `Tools\Github.bat` und unter Linux
ueber `./Tools/Github.sh`. Oeffentliche Pulls laufen auf beiden Hosts anonym.
Das DevKit wird mit `-Pull -DevKit` bezogen; seine hostspezifische Einrichtung
bleibt Eigentum des DevKit-Repositories. Danach wird es unter Windows mit
`DevKit\Setup\Setup_Windows.bat` oder unter Linux mit
`./DevKit/Setup/Setup_Linux.sh` eingerichtet. Beide Starter verwenden dieselbe
PowerShell-Logik; unter Linux werden die festgelegten nativen Toolchains und
Hosttools installiert beziehungsweise gebaut.

Der gemeinsame Build startet unter Windows mit `Tools\Build.bat` und unter
Linux mit `./Tools/Build.sh`. Beide rufen dieselbe PowerShell-Orchestrierung
auf. Repository-Buildstarter und Hosttools werden passend zum Host als
`Build.bat`/`Build.sh` und mit beziehungsweise ohne `.exe` gewaehlt.
Image-Erzeugung, Verifikation und QEMU bleiben Eigentum des
Distribution-Repositories und stehen mit den passenden Hostwerkzeugen
unter Windows und Linux ueber die gemeinsame PowerShell-Logik bereit.

`Tools\Clean.bat` und `./Tools/Clean.sh` verwenden ebenfalls dieselbe
PowerShell-Logik. `Artifacts/Distribution` und `zig-out` bleiben erhalten.

Komponentenquellen, installierte Werkzeuge, Buildartefakte und Zugangsdaten
werden nicht in diesem Repository gespeichert.
